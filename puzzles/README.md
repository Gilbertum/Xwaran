# XWARAN · Puzzle Room

Сайт для совместной сборки артов чатом во время разговорного стрима. Это **самостоятельная разработка**, не копия исходного кода или оформления Tanggle.

## Что умеет

- Настоящие фигурные детали пазла, перемещение мышкой/пальцем, фиксация правильной позиции.
- Общая доска с синхронизацией через Supabase Realtime; гостям **не требуется аккаунт**.
- Пак из нескольких артов, порядок артов и удаление в панели ведущей.
- Импорт изображений прямо с сайта (PNG/JPG/WEBP), автоматическое преобразование в WEBP до 1600 пикселей.
- Сложность каждого загруженного арта: 2–8 колонок и 2–6 строк (для небольшого чата 5×4).
- **Через 5 секунд после последней детали** сервер разрешает переход к следующему арту. Любой онлайн-участник запускает переход; после последнего — поздравление.
- Никнеймы и небольшой зачёт собранных деталей.
- Демо работает сразу и без подключения. Для совместной игры **нужны Supabase и публикация сайта**.

## Как запустить на GitHub Pages

1. Для отдельного репозитория: создать новый **публичный** репозиторий `xwaran-puzzles` и поместить файлы в его корень. Для размещения внутри действующего сайта `Gilbertum/Xwaran` использовать отдельную папку `puzzles/`, не меняя корневую страницу.
2. Для нового репозитория: в `Settings → Pages → Build and deployment` выбрать `Deploy from a branch`, ветку `main`, папку `/(root)`. Для уже настроенного сайта `Gilbertum/Xwaran` можно использовать `https://gilbertum.github.io/Xwaran/puzzles/` после коммита файлов в папку `puzzles/` и успешной сборки Pages.
3. Открыть Supabase → New project. Бесплатный тариф можно использовать для теста; неактивные бесплатные проекты могут ставиться на паузу. Выбрать регион с приемлемой задержкой для аудитории.
4. В Supabase `SQL Editor → New query` вставить весь `setup.sql`, нажать `Run`.
5. В `Authentication → Users` создать пользователя ведущей с email и паролем (подтвердить email при необходимости). НИКОМУ не сообщать пароль.
6. В SQL Editor отдельно выполнить (подставив **реальный** email; запрос не нужно сохранять в GitHub):
   ```sql
   insert into public.admins(user_id)
   select id from auth.users where email='ТВОЙ_EMAIL'
   on conflict do nothing;
   ```
7. В Supabase `Project Settings → API Keys` взять **publishable key** или старый `anon` key и `Project URL`. Никогда не брать `secret` или `service_role`.
8. На опубликованном сайте нажать `Настройки` → вставить Project URL и publishable key → `Сохранить и подключить`.
9. В блоке `Комната ведущей` войти email+пароль → создать пак → выбрать пак → загрузить свои арты → `Запустить пак`.
10. Нажать `Ссылка чату`, отправить ссылку в Twitch/Telegram/Discord. В ссылке есть **публичный** ключ конфигурации (это нормально), уникальный ID комнаты. Гостям не нужно ничего настраивать.

> **Важно:** на странице GitHub Pages без настройки Supabase работает **только локальное демо**. GitHub Pages не хранит общий прогресс и не принимает загрузки — эти функции обеспечиваются таблицами и Storage Supabase.

## Сценарий тестирования

1. Открыть сайт в двух независимых окнах (второе — инкогнито).
2. Ведущая загружает два изображения в один пак, запускает комнату.
3. Гость переходит по приглашению, вводит ник.
4. Переместить несколько деталей в первом окне на правильные места; убедиться, что они появляются во втором.
5. Собрать последнюю деталь, проверить обратный отсчёт 5→0, автоматическое открытие второго изображения в обоих окнах.
6. Собрать последний пазл — увидеть поздравление и итоги.
7. Перезагрузить страницу посреди партии: прогресс сохранится.

## Сбои и восстановление

- **Пустые паки / permission denied:** SQL-скрипт не запущен, неверный публичный ключ или email ведущей не внесён в `admins`.
- **У зрителя не открывается пазл:** отправлена не полная ссылка из кнопки `Ссылка чату` или Supabase недоступен.
- **Зависло обновление при редком обрыве Realtime:** сайт опрашивает БД каждые 20 секунд; можно обновить страницу.
- **Ошибка загрузки:** только PNG/JPG/WEBP, до 18 МБ исходник. Переработанный WEBP должен вписаться в лимит Storage 10 МБ.
- **Сетка некорректно выглядит на мобильном:** перевернуть экран горизонтально; большие паки удобнее на ПК.
- **Откат:** на GitHub Pages вернуть предыдущий коммит. Данные Supabase сохраняются. Перед удалением SQL-таблиц сделай экспорт изображений из Storage.

## Безопасность и границы

- Таблицы/Storage защищены RLS: редактировать паки и арты может только администратор.
- Двигать детали комнаты может любой зритель с действующей ссылкой. Это публичная игра, поэтому **нет защиты от злонамеренной активности внутри комнаты**, спама RPC или подмены никнейма. Для большой аудитории понадобятся Twitch OAuth, rate limiting и модерация.
- Данные зрителей ограничены выбранными никнеймами. Пароль ведущей хранится только в Supabase Auth, не в коде сайта.
- Публичные ключи в приглашении допустимы; **никогда** не передавай secret/service_role key.
- Не редактируй состав пакета во время активной сборки: текущая комната использует порядок изображений из пака.
- Работает без сборщика и npm. Для проверки геометрии: `node tests.js`.

## Технические детали

Frontend: HTML/CSS/Canvas/vanilla JavaScript, Supabase JS 2.x из CDN. Backend: Supabase Postgres + RLS + Storage + Realtime + транзакционные RPC. Хостинг: GitHub Pages или любой статический HTTPS сервер.

**Проверено локально:** синтаксис JS, тесты сетки и snap. **Требует теста после подключения Supabase:** авторизация, RLS, загрузка через Storage, Realtime, одновременные перемещения и публикация GitHub Pages.
